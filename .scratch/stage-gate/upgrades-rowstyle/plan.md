## Goal

After a completed run, every row of the Upgrades tab's settled tables (shortlist, below-cutoff group, slot panes) and of the mid-run provisional table renders with the Gear tab item list's visual idioms — 3rem icon, 1.125rem quality-coloured name, zebra striping, hover background — and carries two new trailing cells: a favorite star and an add-to-Batch-Sim button. Both buttons are built by one shared module that the Gear list also uses, and the row look comes from one shared SCSS partial both tables consume. Clicking the star on an Upgrades row lights the same item's star in the Gear list and vice versa; clicking the batch button adds the item to the Batch tab and the Batch tab's own removal unlights the row. Rank order is untouched. The Gear list looks and behaves as before. A `gate-visual` handoff cites side-by-side captures of both tables at 1280 and 375, the a11y counts are not above baseline, the layout gate is green, the desktop gate's golden readback is unchanged, and the main repo is re-pinned with `pnpm verify` green.

## Approach

**Chosen: Option A as decided — keep the `<table>`, converge by mixins and a shared toggle module.** Row-level look (zebra, hover, icon size, name size) moves from `LIST_SCSS` into `ROW_SCSS` as mixins that `.selector-modal-list-item` (Gear) and `.upgrades-results-table` rules (Upgrades) both include. The two buttons are rendered by `TOGGLES` with the Gear list's exact class names, tippy copy and `trackEvent`, so their button rules move to `ROW_SCSS` by class name. The new cells are appended as columns 6 and 7 — after Source, as two separate `<td>`s — so every existing `nth-child(3)`/`nth-child(4)` rule, the layout gate's column probes and the desktop gate's positional readback of `td[0..4]` stay valid (C20, C21, C33 rev 2). The Upgrades tab refreshes button state through two tab-level subscriptions plus DOM queries under its own `contentContainer`, not per-row `.on()` calls, because its rows re-render on every landed row mid-run and a per-row subscription would accumulate listeners (C14, C15 rev 2).

**Rejected: adopt `.selector-modal-list-item` on the `<tr>` by class name.** That class is `display: flex` with padding on the row box (`LIST_SCSS:78-84`); on a `<tr>` it destroys table layout, and Bootstrap paints every `td` with its own `background-color` plus an inset box-shadow layer (C13 rev 2), so a row-level `background` would be hidden anyway. Mixins let each table apply the same tokens to the element that actually paints.

**Rejected: mid-run table keeps five columns.** `resultsTableHead` and `sortableResultsTableHead` deliberately render one column set so the tables cannot drift (`TAB:481-487`, tickets 278/289); a mid-run row is a real item the reader may want to favorite while waiting. See open question 2.

### Open question 1 — which classes move, and class or mixin (rev 2: hover mechanism)

Candidate: `ROW_SCSS` receives (a) the `:root` cell-width variables (`LIST_SCSS:1-6`), (b) mixin `item-row-zebra-hover($prop)` carrying the `nth-child(2n)` / `nth-child(2n+1)` / `:hover` colours of `LIST_SCSS:85-95`, where `$prop` is the property each host sets for **all three** rules — `background` for the Gear `<li>`, `--bs-table-bg` for the Upgrades `<tr>` (C13 rev 2) — so zebra and hover go through one mechanism per host; (c) mixin `item-row-icon` (`LIST_SCSS:148-153`: `wowhead-background-icon`, 3rem, `--border-default`); (d) mixin `item-row-name` (`LIST_SCSS:155-161`: 1.125rem, `letter-spacing: normal`, `font-weight: normal`); (e) the class rules `.selector-modal-list-item-favorite, .selector-modal-list-item-compare { width: var(--icon-cell-width) }` (`LIST_SCSS:173-176`). `LIST_SCSS` keeps its selectors and includes the mixins; `TAB_SCSS` includes (b) on `tbody tr` with `$prop: --bs-table-bg`, (c) on `.upgrades-item-icon` inside the `≥md` block, (d) on `.upgrades-item-name`; (e) applies to both tables by class name because both render the same button markup. Row padding is not shared: the Gear row pads the `<li>` 0.5rem; the Upgrades `td` already pads `--spacer-2 --spacer-3` at `≥md` (`TAB_SCSS:950-955`), and vertical `--spacer-2` = 0.5rem is the value that matters for row height.

Win condition, stated before measuring: at 1280 the `pnpm tab-review` `style:` facts on the first Upgrades row equal the same facts on a Gear-list row captured by the same script: `.upgrades-item-icon` width/height = `.selector-modal-list-item-icon` width/height; `.upgrades-item-name` font-size = `.selector-modal-list-item-name` font-size; `td` `background-color` of row 1 = `li:nth-child(1)` `background-color`; hovered row-2 `td` `background-color` = hovered `li:nth-child(2)` `background-color` (both read as `background-color` because on the `td` the inherited `--bs-table-bg` is what Bootstrap's `background-color` resolves to, C13 rev 2). Source values these should resolve to: icon 3rem, name 1.125rem, odd row `#222328`, even row `#18191e`, hover `#323232` (C10, C11, C12). Measurement: Step 7's manifests (facts `iconW`, `nameFs`, `rowBg1`, `hoverBg`) on both entries.

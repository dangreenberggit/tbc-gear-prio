| F1 | blocking | Approach S2; steps 4, 5, 8, 9 (assertion (c)) | **S2 cannot observe the traffic it claims to count.** Every sim HTTP request is issued by `fetch()` inside a *dedicated Web Worker* (`worker_pool.ts:357` `new window.Worker(SIM_WORKER_URL)`; the POST is `worker_http.ts:30-35`). In CDP a dedicated worker is its own target (`type: "worker"`) with its own Network domain. `Network.enable` on the **page** session — which is all step 4 specifies, and all `ret-p5-run.mjs`'s `attachPage()` (lines 168-175) ever attaches — never receives `Network.requestWillBeSent` for worker-issued requests. So `requests.bulkSimAsync` is **structurally 0 on every run, including a true desktop HTTP run**. Gate assertion (c) then fails on the tip (step 9 acceptance "rc 0" is unreachable), and — worse — N1/N2 would "pass as expected" for the wrong reason, making the two negative runs prove nothing about S2. Fix: `Target.setAutoAttach {autoAttach:true, waitForDebuggerOnStart:true, flatten:true}` on the page session; on each `Target.attachedToTarget` with `targetInfo.type==='worker'`, send `Network.enable` on that sessionId then `Runtime.runIfWaitingForDebugger`; count across worker sessions. | `sed -n '350,365p' <fork>/ui/core/worker_pool.ts` → `this.worker = new window.Worker(SIM_WORKER_URL);`; `sed -n '29,35p' <fork>/ui/worker/worker_http.ts` → `fetch(\`${baseURL}/${endPoint}?requestId=…\`, {method:'POST'})`; `sed -n '167,180p' <core>/.scratch/stage-gate/upstream-catchup-chunk1/ret-p5-run.mjs` → only `Page.enable`/`Runtime.enable`. ## What must change before execution

F1 and F2 are one defect and they invalidate the plan's central claim: as
specified, S2 reads zero on every run, so "the gate cannot pass on the WASM
fallback" is currently true only by accident — the gate cannot pass on the
*real desktop run* either, and both negative runs would appear to succeed for a
reason unrelated to transport. F3 is separate and is the coverage question the
reshape was asked to answer: the baseline scalar measures the route the
transports already agree on and leaves the screened path — the one place they
provably differ — asserted by nothing. F6 is the work-losing step.

Everything else is fixable in place. C5, C14 and C20 are all honestly labelled
and only C14 is load-bearing in a way the plan does not handle (F8).

**Lockfile discipline.** After *any* fork commit, in the same sitting: re-pin
`data/wowsims-fork.lock.json` to the new tip **and** regenerate
`data/sim-implemented-effects.json` (`python
scripts/generate_sim_implemented_effects.py`), which is keyed on the fork
commit. Skipping it fails `pnpm verify` on a stale-artifact check, not on the
drift gate — which sends you looking in the wrong place. This bit twice.

**Two gates now guard the bundled data**, both in `pnpm verify`:
`pnpm fork-universes:check` (the eight copied files byte-match their `data/`
sources; `--write` refreshes) and `pnpm pool-listings:check` (the two committed
pool listings match a fresh regeneration). Both are byte-compares, not
judgements: a regen that drops an item passes once someone commits it. The
protection is that the diff names items.

**Build recipe.** The corrected one is
`.scratch/stage-gate/finish-the-tab/measurements.md:1054-1075` — protoc ×4,

### Browser-measurement traps

- **Serve `dist`, not `dist/tbc`.** The bundle hardcodes a `/tbc/` prefix, so
  serving `dist/tbc` as the web root 404s the entry script and the page renders
  **blank white with no console error**. Correct:
  `cd vendor/tbc-new-fork/dist && python -m http.server 8975`, then
  `http://localhost:8975/tbc/druid/feralcat/`. Feral's route is `feralcat`.
- **The extension can open your tab in a 0×0 window.** Such a tab reports
  `visibilityState: hidden` **permanently**, however the owner fronts their
  windows — indistinguishable from "nobody fronted it", and polling never
  fixes it. Diagnose with `window.outerWidth/outerHeight`; fix with the
  extension's `resize_window` (1600×1000 worked).
- **A background tab is not a measurement surface.** Throttled, a run took ~6
  minutes to reach its first sim.
- **An empty filter view renders a one-cell "No upgrades found above the
  cutoff." row.** A naive `tbody tr` count treats it as data — it inflated a
  filter's row count and produced a phantom item matching three filters. Count
  only rows with `cells.length >= 5`.
- **The console tracker re-initialises on every navigation**, so it never sees
  load-time logs such as the worker banner. Read the fact at its source
  instead: `new Worker('/tbc/sim_worker.js')` posts
  `{"msg":"ready","outputData":{"0":1}}`, where `outputData[0] === 1` is
  `isWasm` true.
- **Verify a bundle by gear-set item id, not a source identifier** — oxc
  minification renames identifiers.
- **Rebuild `lib.wasm` whenever you rebuild `sim_worker.js`**, even with no Go
  change. A stale wasm never instantiates under newer glue and fails
  **silently**: no gear, no presets, empty Settings, no error.

### Editing fork files from Python

Pass `newline='\n'`. `pathlib.write_text()` without it translates to CRLF on
Windows, `core.autocrlf=false`, and there is no `.gitattributes` — two commits
flipped whole files to CRLF and had to be rewritten. **Check `git diff --stat`
is content-sized before every fork commit.** Note
`upgrades/engine/PROVENANCE.md` is genuinely CRLF at rest; leave it alone.

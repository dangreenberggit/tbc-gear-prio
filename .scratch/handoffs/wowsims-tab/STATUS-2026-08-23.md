**Owner ruling, 2026-08-23: there is no time target.** D7 (`PLAN.md:61`) sets
an iteration default and carries no time number; the 600 s column above was
this plan's reading of `candidate-pool.md:11`'s "single-digit minutes" and is
kept only as the yardstick the cells were judged against when they ran. The
elapsed figures stand as measurements. Speed-ups (caching — useful at least for
development — worker count, other tricks) are later work; fixing the sim
process itself is not this project's job. How the tab drives the sim today: one
full `RaidSimRequest` per candidate at 3,000 iterations, up to
`min(workers, memoryCapFromDeviceMemory())` (default 4) in flight
(`wasm_sim_runner.ts:112-152`, `rank.ts:777-798`); wowsims' own Batch tab also
runs one full sim per combination, so there is no cheaper bulk path to reuse
(`wasm_sim_runner.ts:12-23`).

Two figures recorded without explanation: **7.8 s per sim** here against ticket
156's 3.8 s, and a **17 % spread** between two runs of the same ret prune-off
cell (866 s and 1017 s).

Two caveats that bound what these numbers mean:

- **The ret baseline is unreconciled.** The page reported 1775.0 DPS for the
  `slamaltman` fixture; this repo recorded **2042.85 DPS** for the same fixture
  at 3,000 iterations. 13 % apart, cause unknown — candidates are a differing
  encounter/buff set through `toIndividualSimSettings`, and 16 item ids
  persisting where 17 slots exist. **Ticket 274.** The cell-to-cell comparisons
  above are self-consistent; the absolute DPS is not trustworthy.
- **The feral cell ran the fork's default APL.** The owner's rotation was
  stripped before decoding (`timeToNextEnergyTick` is unknown to the pinned
  proto). The 61 s, the 395 s and "no rankable set potential on feral" all
  inherit that.

## Q1–Q7 decisions

- **Q1 — sim strategy.** Candidate (c), **full sweep**, wins. Racing is deleted
  (`f70378155`). Decided by the plan's pre-stated rule, not by a fork-side
  measurement: cell 3 was never run because that archive would not load gear
  (**ticket 273**). ADR-0026's core measurements (1.407 / 1.476 / 1.098 times
  the full sweep, never clearing 20 %) are what justify the deletion. Tickets
  205 and 206 closed as moot.
- **Q2 — ticket 156.** Closed with the numbers above. **D7 stays 3,000.**
- **Q3 — §9 item 7 scope.** More specs: out, tranche 2. IndexedDB cache: out —
  `MemoryStore` already dedupes identical sim requests within a page session,
  and a cross-session store is a fourth `Store` adapter with its own
  invalidation story. Local-sim port: out, upstream-shipping work.
- **Q4 — engine drift.** Racing removal ported; the other four core changes need
  no action (`set-potential.ts` split is inlined, `candidates` on the `simming`
  event is unused by the tab, the index exports have no fork counterpart,
  `HIT_CAP_PERCENT` is already present). Drift gate: `ok: 32 ported files`
  (was 33; `promotion.ts` deleted).
- **Q5 — set-bonus toggle.** Binary `withSetPotential` checkbox. **Win condition
  met**: toggling a completed ranking reordered 12 rows with zero sim calls.
  Replaceable by a three-state control — state is read only through
  `currentViewOptions()`, never persisted, i18n key `view.set_potential`.
- **Q6 — post-sim BIS filter.** A filter, not `pinBis`. 480 rows → 32 → 480,
  reversible, no sims, slot tabs intact.
- **Q7 — pre-sim prune.** Built, sourced from the universe's own `bisTags`.
  Placeholder tracks the control (240 → 16 ret, → 17 feral). Tags-only, and that
  changes only which candidates are simmed: the baseline is the gear on the page
  either way, so deltas mean the same thing in both runs. An untagged worn item
  simply gets no greyed "already have it" row. The drawer names the pool used.

## Traps this run hit, so the next one does not

- **Rebuild `lib.wasm` whenever you rebuild `sim_worker.js`**, even with no Go
  change. Plan claim C22 said otherwise and was wrong. A wasm built by an older
  Go toolchain never instantiates under newer glue, and it fails **silently** —
  no gear, no presets, empty Settings, no console error. Check for
  `Worker[0] Ready, isWasm: true`.
- **Verify a bundle with a gear-set item id, not a source identifier.** oxc
  minification renames identifiers; grepping for `makePresetGear` produced a
  false "the presets are missing" conclusion.
- **`cd` into the fork is fine after `fnm env` + `fnm use 22.17.1`**, and the
  vite build *requires* it (`vite.config.mts:128` resolves `assets/locales`
  against the process cwd). The no-`cd` rule only applies before fnm is set up.
- **Do not run `npm run format` in the fork.** It is a writer, and the tree is
  not oxfmt-clean — it rewrites ~693 files.
- **A background tab is not a measurement surface.** Throttled, the same run
  took ~6 minutes to reach its first sim; fronted, it did 2 sims in 16 s.

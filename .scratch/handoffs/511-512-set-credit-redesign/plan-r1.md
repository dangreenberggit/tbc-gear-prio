## Approach

**Findings.** `.scratch/stage-gate/upgrades-tab-closeout/round-2e/d1-noise.md`: a net 4pc value is a difference of 5–6 sims; its combined `se` at 3000 iterations is 5.2–6.6 DPS (verification.md V0a–V0c), so the 4.81 floor is below one `se` and scenario H's +9.5 (1.4–1.9 se) is plausibly noise. Scenario I's +21.1 and +15.3 are 3–4 se and are probably **not** noise. The 4pc `se` also omits the `se` of the subtracted 2pc term (a defect in the `rank.ts` set block). Candidate (a), gate at k×se, meets its pre-written win condition at no k (k=2 keeps CF4 +21.1; k=3 drops the real Nordrassil 4pc +19.9). Candidate (b), 5× iterations, fixes H but not a systematic I. Candidate (c), per-spec inert marking, is the only one that removes I's credit, and the Go closures make heal (`CalcAndDealHealing`) and mana (`SpellMod_PowerCost_Flat`) visible, but J4 is a damage mod whose inertness is an APL fact, so (c) is a hand judgment. `d3-sets.md`: the sim ties sets to items by `Name` (and `ID` when the Go literal has one); ~60 `NewItemSet` registrations, thresholds 2/3/4/6/8; `scripts/generate_sim_implemented_effects.py` already scans the fork tree with a lock guard and a `verify` check, but does not read `NewItemSet`; the name→setId join is available in `data/items/index.json`. Feral pre-raid wears Wastewalker 659 4/4 in exactly the four Malorne slots; ret pre-raid wears Burning Rage 566 2/2 in exactly the two Justicar slots. About 17 files mention `SetThreshold`; ~7 sites carry a semantic 2-below-4 assumption.

**Chosen.** D3 by design A: extend the existing generator to emit a `setId → implemented thresholds` table into a committed JSON plus a generated TS literal in both engine copies, with a hand `TABLE_OVERRIDES` map for judgment cases (Justicar 2pc, and the D1 per-spec inert bonuses). D1 by candidate (c) plus the `se` defect fix, preceded by a probe that decides whether a further engine change is needed this round. One round, serial slices (probe → D3 → D1 → fixtures → SME → gates), because D1's override lives in the table D3 reshapes and the executor is one seat with one fork clone.

**Rejected.** Extend the hand table (design B): same lines, but no gate catches drift on the next pin move, and it repeats the ticket-301 re-mirror pattern the owner rejected. Gate on k×se (candidate a): fails its own win condition on the numbers on disk. More iterations (b): 8–22 min per run upper bound and leaves scenario I untouched. Two rounds: rejected because the D1 override needs the D3 table shape; splitting would touch `set-value.ts` twice under PROVENANCE.

## Answers to the six questions

1. **Calibration rule.** It is only a partial fix for F2. A non-DPS bonus can get through on its own package's residue, and J4's R does not bound other packages (N1). Absolute-value admission also admits residue (N2). Measuring once per pin on one gear set per spec wrongly drops real bonuses whose value depends on gear, gives them a false label, and has no staleness gate (N3). Sets that are only worn have no se definition (N4).
2. **C9.** Right for the 2pc-prefix case with raw-sim se inputs. It is undefined for J4, the probe's own case. It is ambiguous about delta se versus raw se, and the pair coefficient is wrong (N5).
3. **Temporary fork edits.** Measuring on :5173 is right for the TS engine. The Go backend's build is not checked (N6). The revert is complete. The verdicts are written in advance and decide, apart from the dead proceed branch (N9) and the negative-J4 gap (N2). A1's table turns on J2 and so corrupts the probe (N8).
4. **B6.** The named scope is right, but it leaves out the only-worn calibration question (N4) and the upstream-versus-fork mismatch (N11). I did not confirm that the committed report artifacts read by `rank-package-artifacts.test.ts` stay valid. The file header says the tests "re-derive from the artifacts' `setBonuses`", so they probably are; B3's test run would show it.
5. **B1/B2 pattern.** It matches the existing JSON-to-core-TS plus fork-copy compare, but it cannot finish because of `forkCommit` (N7), and CI does not check it (N12).
6. **2/4 guard and the 492 pair guard.** Both are resolved. The guard keeps the pair maths for 2/4 sets only, and nothing in the 492 block changes.
